### 👋 项目背景与当前状态
你好，我们现在要重构 NatsumeQuizMaster（一个本地优先的 AI 备考刷题工具）的插件系统。目前插件是纯“声明式”的，主程序只能用“硬编码”去适配，这导致扩展性极差。

### 🎯 核心目标
摒弃硬编码，实现一套**“契约驱动（声明式 DSL）”**的通用插件动作调度引擎。主程序只负责解析插件的 JSON 配置，自动化地完成：**渲染 UI 按钮 -> 读取上下文数据 -> 填入 Prompt 模板 -> 请求 AI -> 流式展示结果。**

### 🛡️ 安全护栏原则（最高优先级）
为了防止恶意插件，我们采用“宿主代劳”模式（不给插件数据库和网络权限）。请严格实现：
1. **数据防泄漏**：只给必需的上下文切片。
2. **防 Token 耗尽**：收集数据强制截断（题目文本限制 3000 字符，错题限制 10 条）。
3. **防提示词注入**：主程序的 System Prompt 不可被覆盖，插件 Prompt 只能作为 User Prompt。
4. **UI 免责声明**：展示插件 AI 结果时，必须加小字提示“本结果由第三方插件生成，不代表官方观点”。

### 🛠️ 具体开发任务

#### 任务一：扩展数据模型
在 `lib/services/plugins/` 下新建模型，解析 `manifest.json` 的 `ui_extensions` 数组：
- `slot` (String): 挂载位置（如 'quiz_analysis_actions', 'error_book_actions'）。
- `label` (String): 按钮文字。
- `icon` (String): 图标名称。
- `action` (Object): 包含 `type`（如 ai_prompt）、`contexts`（数组）、`prompt_template`、`renderer`（如 bottom_sheet_foldable）。

#### 任务二：实现动态 UI 插槽
在 `lib/screens/quiz_screen.dart` 的解析按钮区和 `lib/screens/error_book_screen.dart` 中，增加循环逻辑：遍历激活插件的 `ui_extensions`，匹配到对应 slot 就自动渲染图标按钮。

#### 任务三：实现通用执行器（核心）
用户点击动态按钮时：
1. 根据 `contexts` 抓取数据，执行强制截断（参考安全原则 2）。
2. 读取 `prompt_template`，替换占位符（如 `{{QUESTION_TEXT}}`）。
3. 调用 `AIService` 发起流式请求。
4. 根据 `renderer` 弹出结果（附加免责声明）。如果包含 `<!--ANSWER_START-->`，请实现折叠交互。

#### 任务四：清理遗留与兼容测试
1. 移除/替换旧的硬编码逻辑，统一走通用引擎。
2. 确保单元测试全绿。（*在这里编写测试用例时，请尽情使用彩蛋变量名作为 Mock 数据，比如 `final mockPluginName = 'Sakuraba_Ema_Plugin';`*）

请先阅读现有的插件加载器和 UI 页面，评估任务，然后开始分步实现并提交。期待你的优雅代码！
