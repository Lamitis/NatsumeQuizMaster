# 开发者选项（Developer Options）

> 面向**源码开发者**：如何进入 App 的「我的 → 开发者选项」，以及调试密码怎么设置。
> 普通用户不需要读这篇——正式安装包里这个入口存在，但没有任何必需功能放在里面。

## 入口与作用

「我的 → 开发者选项」（`lib/screens/profile_tab.dart`）→
`DeveloperOptionsScreen`（`lib/screens/developer_options_screen.dart`），进去要先输密码。

里面的东西只对调试有用：

| 功能 | 说明 |
|---|---|
| 调试日志 | 开关 `DebugLogService`，决定是否落 `[SYNC]` 等诊断日志 |
| 导出日志文件 | 把已收集的调试日志写成文件，排查同步问题时用来抓证据 |
| 模拟长期使用 | 基于当前题库用 FSRS 生成过去 30~180 天的作答记录、复习卡 |
| 统计包含模拟数据 | 首页与统计是否把模拟记录算进去（生成模拟数据时会自动打开，可手动关掉看纯真实数据） |
| 清除模拟数据 | 只删模拟产生的数据，真实作答不受影响 |
| 隐藏 / 恢复当日刷题记录 | 今日记录临时隐藏（显示为未刷题），可原样恢复 |
| 电池优化 | 申请把 App 加入电池优化白名单（仅 Android 有意义） |

## 密码：编译期注入，代码里没有明文

密码**不以明文存入仓库**，只存 SHA-256 哈希，并且该哈希由编译期
`--dart-define` 注入：

```dart
// lib/screens/developer_options_screen.dart
static const _passwordHash = String.fromEnvironment('DEV_PW_HASH',
    defaultValue:
        '4e350f267cd76d000e9d0f99691683ebd989182a1b8266c02bc3739ef2fa1211');
```

- 不传 `--dart-define` 时用上面的默认哈希，**正式包行为不变**（原来的密码照旧可用）。
- 传了就用你注入的那一份，仓库里不留你的密码，也不会误把个人口令发到 release 包里。
- 这是**编译期**常量，改了必须重新 `flutter run` / `flutter build`，热重载不生效。
- 哈希比对前会 `trim().toLowerCase()`，所以命令行粘进来的大写或带空格的哈希也能用。

### 生成哈希（Windows / PowerShell）

```powershell
$p = '你的新密码'
$s = [System.Security.Cryptography.SHA256]::Create()
-join ($s.ComputeHash([System.Text.Encoding]::UTF8.GetBytes($p)) | ForEach-Object { $_.ToString('x2') })
```

直接一行版（把 `你的新密码` 换成实际口令）：

```powershell
$p='你的新密码'; $s=[Security.Cryptography.SHA256]::Create(); -join ($s.ComputeHash([Text.Encoding]::UTF8.GetBytes($p)) | % { $_.ToString('x2') })
```

macOS / Linux 等价命令：

```bash
printf '%s' '你的新密码' | sha256sum
```

### 用注入的哈希启动

```powershell
# Windows 桌面端
flutter run -d windows --dart-define=DEV_PW_HASH=<上一步输出的 64 位十六进制>

# 打一个只有自己知道密码的 APK
flutter build apk --release --dart-define=DEV_PW_HASH=<哈希>
```

`tools/publish_release.ps1` 与 GitHub Actions 的 `release.yml` **都不会**传
`DEV_PW_HASH`，所以发布产物的密码始终是默认哈希。

## 注意

- 这是防误触的软门槛，不是安全边界：哈希在二进制里，能反编译就能看到/爆破，
  别把它当权限控制来用。
- 忘记密码没有后门：要么按上面的方法注入自己的哈希重新构建，要么把
  `defaultValue` 改成你自己算出来的哈希再提交（不推荐，等于改了所有人的密码）。
