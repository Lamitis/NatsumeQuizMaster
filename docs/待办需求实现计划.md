## 0.11 知识库接地接进解析 / 追问——**已实现（2026-10-29 · v1.34）**

**背景**：v1.32 审计发现约束块「接口齐了、没接上」——`GroundingService.buildBlock`
全工程零调用方，`streamAnalysis` / `streamFollowUp` 的 `grounding` 参数恒为 null，
README 与知识库页当时的「AI 解释只依据这些资料」是过度承诺。

**用户口径（决定方案）**：「将知识库接地接进解析，但并不是完全依赖知识库的解析，不禁止
AI 本身的解析，因为知识库不一定全面」。所以**没有**照搬原方案 A（显式选库 + 硬约束
「只允许依据资料」）——那样一本生理学知识库会让病理题解析直接拒答，比幻觉更难用。

| 层 | 实际改动 |
|---|---|
| 提示词 | `grounding_service.dart` 新增 `buildSoftBlock(hits, {maxCharsPerHit, maxHits})`：资料优先、资料没覆盖的部分允许模型用自己的知识补全并声明「通用知识」、冲突时以资料为准；原 `buildBlock`（硬约束）保留给 AI 出题链路，一字未动 |
| 服务层 | `app_state.dart` `_resolveGrounding(q)`：`KbService.listKnowledgeBases()` + 逐库 `search(题干 + 选项, topK: 4)` 合并排序 → 最高分 40% 相对阈值 → 取前 4 片拼块。四道闸门：开关关/未配 Key、题干 <4 字、无库/无命中/最高分 ≤0、相对阈值；任一不满足返回空串（= 旧行为）。检索异常只记 `DebugLogService`，按「无资料」继续 |
| 接线 | `_loadAnalysis` 先 `_cancelAnalysisStream()` 拿代次再检索（检索期间切题用「代次 + 题号」双守卫，不会把 loading 卡在新题上），块存 `_analysisGroundingBlock` 并传给 `streamAnalysis(q, grounding:)`；`sendFollowUp` 复用同一块传给 `streamFollowUp(grounding:)`；换题 / 重答 / 未配 Key 时清空 |
| 开关 | `AppSettings.analysisGrounding`（settings 键 `analysis_grounding`，默认开，不涨 schema）+ `AppState.setAnalysisGrounding(on)` / `regenerateAnalysisWithGrounding()`；AI 对话页右上角「知识库引用」按钮切换，打开即用资料重跑当前题解析 |
| 可见性 | 解析真的用到资料时，AI 对话页在题目卡下显示「本次解析引用了已导入的知识库（资料优先，未覆盖部分由 AI 补充）」（`AppState.analysisGrounded`） |

**与本文原方案的差异（有意为之）**

- 原方案 A「每题手动选库 + 硬约束」被否：用户要的是「接进解析」而不是「手动触发一次」，
  且硬约束违背「知识库不一定全面」这条前提。
- 原方案 B（题库↔知识库绑定，整场会话注入）需要题库与知识库的绑定关系，仍待后续做；
  本次用「全库检索 + 相对阈值」近似达到同样效果，且不需要用户先绑定。
- 原方案 C 的覆盖率门槛需要 `KbRetriever` 另出置信度；本次先用 BM25 最高分的 40% 相对
  阈值代替，够用且零额外改造。

**验收（人工）**：导入含「动作电位」章节的知识库 → 刷到相关题时提示词含「【资料1】…」，
回答标注「依据你导入的资料」；问库里没有的知识点 → 仍给出通用解释并声明；关掉对话页
「知识库引用」→ 提示词与缓存行为回到 v1.33。

**已知取舍**：带 grounding 时按 `ai_service.dart` 既有约定**不读不写** `ai_cache`，
所以开引用后每题解析都会真实请求一次（换来的是一题一库一答案、不串味）；没命中资料的题
不受影响，缓存照旧。

## 1. 自由选题：题库范围 + 知识点筛选——**已实现（2026-10-29）**

**现状（v1.31 之后）**：入口已从「定向爆破」改名为**自由选题**，弹层由两段合并为一段
（`quick_start_screen.dart` `_showStartQuizSheet`：题数 chips + 三模式单选 + 「开始」），
抽题逻辑全部走 `QuizLauncher.launch(...)`；题库内题号网格与它共用同一套模式枚举与启动代码。
**v1.33 时的状态**：范围 / 知识点还不能在面板里直接勾选——题库范围当时来自
「管理题库」里事先勾存的 `AppState.selectedBankIds`，一换知识点就得回题库管理页重勾。抽题链路：
`QuizLauncher.launch` → `AppState.startQuizWith(bankIds:, count:, noShuffle:, persistSession:)` →
`QuizService.startQuiz(...)` → `DatabaseService.getQuestionsByBanks(bankIds, random:, limit:)`。


**方案**

1. 数据层：`database_service.dart` 新增
   - `getKnowledgePointsByBanks(List<int> bankIds)`：`SELECT knowledge_point, COUNT(*) ... GROUP BY knowledge_point`（空值归「未分类」）；
   - `getQuestionsByBanks(...)` 增 `Set<String>? knowledgePoints`、`Set<String>? questionTypes`：
     `WHERE bank_id IN (...) AND (knowledge_point IN (...) OR (? 含未分类 AND COALESCE(knowledge_point,'') = ''))`。
2. 服务层：`quiz_service.dart` `startQuiz` 透传筛选参数；`app_state.dart` 增
   `startQuizWithFilter({bankIds, knowledgePoints, questionTypes, questionCount, mode, noShuffle})`，
   抽到 0 题时不建会话（沿用现有防空逻辑）并把「该条件下暂无题目」返回给界面提示。
3. 界面层：新建 `lib/widgets/quiz_setup_sheet.dart`（底部弹层，四段）：题库多选（含全选/反选、
   「已选 N 库 M 题」）→ 知识点多选（随题库联动刷新）→ 题量（10/20/30/50/80/100/全部/自定义）→
   模式（顺序 / 随机 / 只错题）。首页快捷操作与开始页入口统一改唤起它。
4. 兼容：无筛选的「直接开刷」行为不变，仍走 `startQuiz()`。

**验收**：选 2 个知识点共 5+5 题、题量 10 → 抽出的题全部落在这两个知识点；
知识点全不选 = 整库（与现在等价）；筛选后 0 题有明确提示且不产生空会话；
新增 `test/quiz_filter_test.dart` 覆盖 SQL 条件与「未分类」分支。


**落地记录（2026-10-29）**

| 层 | 实际改动 |
|---|---|
| 数据层 | `database_service.dart`：`getQuestionsByBanks` 增 `knowledgePoints` / `questionTypes`（空集合 = 不限，老调用方零改动）；知识点空串代表「未分类」，只有显式勾选才纳入——不勾时整库照旧包含无知识点题；新增 `getKnowledgePointsByBanks(bankIds)` 返回 `[{kp, cnt}]`（空知识点以空串返回，AI 失败标记与正确率排行同口径排除） |
| 服务层 | `quiz_service.dart` `startQuiz` 透传两个筛选参数；`app_state.dart` 新增 `startQuizWithFilter(...)`（`startQuizWith` 委托它，行为不变）与 `getKnowledgePointsByBanks(...)`；0 题沿用既有防空逻辑：不建会话、不清旧进度 |
| 界面层 | 新建 `lib/widgets/quiz_setup_sheet.dart`（`QuizSetupSheet.show` → `QuizSetupResult`）：题库多选（全选 / 反选 / 清空 +「已选 N 库 M 题」）→ 知识点多选（随题库联动刷新，含「未分类」）→ 题量（10/20/30/50/80/100/全部/自定义）→ 三种刷题模式 +「按题库原顺序出题」开关 →「开始」。`quick_start_screen.dart` 改为唤起它，原私有 `_StartQuizSheet` 删除；面板内改范围**不写回** `AppState.selectedBankIds` |
| 用例 | `test/quiz_filter_test.dart`：知识点筛选 / 未分类分支 / 题型与题量 / 顺序出题 / 知识点分布计数（排除 AI 失败标记）/ `startQuizWithFilter` 落库与 0 题不建会话 / 面板勾知识点后结果回传（widget 用例） |

**与本文原方案的差异（有意为之）**

- **「模式（顺序 / 随机 / 只错题）」没有照抄**：面板沿用既有的 `QuizLaunchMode` 三模式
  （正常刷题 / 练习 / 背题），否则题库题号网格与引导文案会跟着漂移；「顺序 / 随机」另做成
  一枚开关（背题模式恒按原顺序并置灰）。「只错题」需要错题本口径的抽题链路，不在本次范围。
- **题型筛选**：数据层 / 服务层在首批落地时就通了，面板入口在 v1.34 补上（现在是五段：
  题库范围 → 知识点 → 题型 → 题量 → 模式；题型不选 = 全部）。用例见
  `test/quiz_filter_test.dart` 的面板 widget 用例（勾「多选」后 `QuizSetupResult.questionTypes`
  回传 `{'multi_choice'}`）。
- **入口不再要求「先去管理题库勾选题库」**：开始页「自由选题」只在一道题都没有时拦一下
  （引导去导入），其余情况直接开面板；面板默认沿用开始页的勾选，未勾选则默认全选——
  点「开始」即可开刷，与知识点「不选 = 全部」是同一口径。

## 2. 题库目录嵌套（多级分组）

**现状**：`question_banks` 平铺一层，`BankManageScreen` 平铺列表，`AppState.selectedBankIds` 直接喂给抽题。

**方案**

1. 数据层：DB `version: 14` → `15`（14 已被双链笔记占用），`onUpgrade` 增列
   `ALTER TABLE question_banks ADD COLUMN parent_id INTEGER` +
   `ADD COLUMN sort_order INTEGER NOT NULL DEFAULT 0`，并建 `idx_question_banks_parent`；
   模型 `models/question_bank.dart` 增 `parentId`、`sortOrder` 与对应 `copyWith`。
2. 服务层：`database_service.dart` 增 `getBankTree()`、`moveBank(id, newParentId)`（校验不能移到自己
   或自己的子孙下）、`getDescendantBankIds(id)`；删除父库时子库升为顶层（`parent_id = NULL`），避免连带删题。
3. 界面层：`bank_manage_screen.dart` 改树形：展开/收起、缩进层级、「⋯ → 移动到…」选父库、新建子库；
   `AppState.selectedBankIds` 仍存「选中库 id」，抽题前用 `getDescendantBankIds` 展开成实际 bank 列表
   （`getQuestionsByBanks` 本身不用改）。
4. 兼容：迁移后所有 `parent_id` 为 NULL → 界面与现状完全一致。

**验收**：三级嵌套抽题覆盖子孙库；删除父库后子库题目仍在；把父库移到自己子孙下被拒绝；
旧库升级后打开无异常（迁移用例放 `test/bank_tree_test.dart`）。

## 3. MinerU OCR 接入——**已实现（v1.30.2）**

**许可结论（2026-10-29 核实）**：MinerU 自 3.1.0（2026-04）起由 AGPL-3.0 切换为
「MinerU Open Source License」，实质是 **Apache-2.0 + 两条附加条款**：

1. **规模门槛**：月活 < 1 亿 且 月收入 < 2000 万美元可免费商用；触及门槛需另行购买商业许可；
2. **署名义务**：基于 MinerU 向第三方提供在线服务（SaaS）时，须在界面或公开文档显著位置
   标明使用了 MinerU。

本工程只调用其**官方在线 API**（不内嵌上游代码/权重/二进制），因此按「在线服务」形态处理：
`MineruService.attribution` 已展示在「设置 → AI 接口 → 扫描件识别增强」，同时导入页提示该能力的位置。

**落地形态**

- `lib/services/mineru_service.dart`：双通道
  - 轻量（默认，免 Token）：`POST /api/v1/agent/parse/file` → PUT 上传 → `GET /parse/{task_id}`
    轮询 → 取 `markdown_url`；限 10MB / 20 页；
  - 精准（填 Token）：`POST /api/v4/file-urls/batch` → PUT 上传 →
    `GET /extract-results/batch/{batch_id}` → `full_zip_url` 取包内最长 `.md`；限 200MB / 200 页。
  - 全链路失败一律返回 `null`（`DebugLogService` 留痕），导入流程按老路继续，不会硬失败。
- 回退顺序（`AppState._parseScannedPdf`）：MinerU → 端上 ML Kit OCR（Android）→ 视觉切题；
  另外「PDF 抽出的文字层 < 200 字」也会触发 MinerU（扫描件混排的常见形态）。
- 知识库 PDF 导入同样在文字层过薄/`PdfExtractException.scanned` 时回退到 MinerU。
- 凭据：`AppSettings.mineruEnabled / mineruToken`，Token 与 API Key 同口径走 `KeyCrypto` 密文入库。

**待办（需联网联调，本轮未验证）**

- 轻量通道 `/parse/file` 的请求字段在官方文档里被截断展示，实现先发全字段、被拒后自动退最小字段
  （`{file_name}`）；拿到真实 Token 后应各跑通一次并把字段收敛成文档版本。
- `full_zip_url` 的下载是否也需要 `Authorization`（当前带上了，若预签名 URL 拒绝多余头需去掉）。
- 解析出的 Markdown 里图片是外链，暂不还原成题目配图（本地抽到的图仍按原逻辑进「待指派」）。

## 4. 知识库 + 题库导出/导入粒度

**现状**：`BankFileService.exportBank(bankId, bankName, destPath)` 只能单库导出、`importJsonFile` 单文件导入；
知识库有独立的 `lib/services/knowledge_base/kb_file_service.dart`；两者互不联动，
用户想「整套资料搬走」只能分别导出多次。

**方案**

1. 新增容器格式 `NatsumePack`（zip）：`manifest.json`（格式版本、库/KB 旧→新 id 映射、导出时间、APP 版本）+
   `banks/<id>.json` + `kb/<id>.json`（文档 + 切片）+ `images/<bankId>/<position>.<ext>` + `meta/fsrs.json`（可选）。
2. 新增 `lib/services/pack_service.dart`：`exportPack({bankIds, kbIds, includeFsrs, includeErrorBook, destDir})`
   与 `importPack(path, {onConflict: merge|skip|overwrite})`；复用 `ExportStorage` 的用户可见目录与
   `BankFileService` 的格式标记；单库导出保持原样（不是 zip，老文件仍可导入）。
3. 界面：导出页给三档粒度——单库 / 多选库 / 全量（全量=所有库 + 所有 KB + 可选错题与复习进度）；
   导入页识别 `.natsume.zip` 后弹「合并 / 跳过重名 / 覆盖」，并显示包内清单预览。
4. 落库：导入走事务，失败整体回滚；重名库按策略加后缀或走 `manifest` 的 id 映射表。

**验收**：全量导出 → 重置数据库 → 导入 → 库数/题数/知识点/KB 文档与切片数一致；
单库导出不含任何 KB；重名导入按选择生效且不产生重复题库（`test/pack_service_test.dart`）。

## 5. 插件生态（本地安装 + 启停）

**现状**：已有 `lib/models/plugin.dart`、`lib/models/world.dart`、
`lib/services/plugins/plugin_loader.dart`、`world_service.dart`、`world_overview_screen.dart`，
但缺「安装包格式 / 校验 / 启停 / 兼容性」这套最小生态闭环，也没有分发模型。

**方案**

1. 包格式：`plugins/<id>/manifest.json` + `assets/` + `entry`；
   manifest 字段：`id / name / version / apiVersion / minAppVersion / publisher / license / checksum(sha256)`；
   目录落在 `ExportStorage` 下的 `plugins/`（用户可见，便于手动拷入）。
2. `plugin_loader.dart`：启动扫描 → 校验 checksum → `apiVersion` 与 `PluginApi.version` 比对
   （不兼容则禁用并显示原因）→ 汇总到注册表；启用/禁用状态存 SharedPreferences。
3. 界面：`world_overview_screen.dart` 增「插件」区：列表（名称/版本/作者/状态）、开关、
   「安装（选 zip）」「卸载」「详情/日志」。
4. 分发模型**待定**（阻塞项）：A. 纯本地 zip（无网络，最简单，先做）；
   B. 自建索引 `index.json` 在线市场（需域名 + 签名）；C. GitHub Release 直链。
   建议先落 A，把 `manifest` 与校验做成 B/C 可直接复用。

**验收**：checksum 不符 / apiVersion 不兼容 / 缺 manifest 三种坏包都被拒绝且不影响启动；
启停后首页与知识库入口按插件声明显示或隐藏；卸载不残留文件。
