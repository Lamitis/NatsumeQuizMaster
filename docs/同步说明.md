# 跨端同步说明（局域网 + Syncthing）

> 追加需求：参考 Syncthing 实现手机↔电脑同步，用户扫码即可配对。

## 两条同步路径

| 路径 | 适用 | 说明 |
|---|---|---|
| 局域网同步（原有） | 同一 Wi-Fi 下 | `SyncEngine` + mDNS 发现 + 识别码/扫码配对，已有实现 |
| Syncthing 同步（新增） | 跨网络、多端 | 经 Syncthing 共享目录持续同步题库/知识库文件 |

## Syncthing 集成方式

- REST 客户端：`lib/services/sync/syncthing_client.dart`（加设备/加目录/状态）
- 后端：`lib/services/sync/syncthing_backend.dart`（扫码配对 + 目录定位）
- 配对载荷：`lib/services/sync/sync_backend.dart` 的 `SyncthingPairPayload`
  （二维码内容 = deviceId + apiKey + folderId）

### 桌面端

捆绑或按需下载 `syncthing(.exe)`（校验 sha256），作为子进程启动，经 REST
（默认 `http://127.0.0.1:8384`，`X-API-Key` 认证）控制；共享目录固定为
`NatsumeQuizMaster数据/`（题库 JSON + 知识库包 + 清单）。

### Android 端

经 gomobile 把 Syncthing 的 `lib/syncthing` 编译成 `.aar`，在进程内跑，暴露
同一 REST 接口与共享目录。原生构建步骤（本仓库只交付 REST 客户端 + 目录监听
契约）。

## 扫码配对体验

复用现有 `sync_qr_view.dart` / `sync_scan_screen.dart`：一端生成二维码
（SyncthingPairPayload），另一端扫 → 互相 `addDevice` + `addFolder`，之后
Syncthing 自动持续同步；App 监听目录变化，经 `KbFileService` /
`BankFileService` 自动导入新文件（按题目内容指纹去重）。

## 许可

Syncthing 为 MPL-2.0；以独立进程/REST 调用方式使用，其文件不并入本仓库。
