# 跨端同步说明（局域网 + Syncthing）

> 追加需求：参考 Syncthing 实现手机↔电脑同步，用户扫码即可配对。

## 两条同步路径

| 路径 | 适用 | 说明 |
|---|---|---|
| 局域网同步（原有） | 同一 Wi-Fi 下 | `SyncEngine` + UDP 广播/多播/单播扫描发现 + 识别码/扫码配对（含握手确认） |
| Syncthing 同步（新增） | 跨网络、多端 | 经 Syncthing 共享目录持续同步题库/知识库文件 |

## Syncthing 集成方式

- REST 客户端：`lib/services/sync/syncthing_client.dart`（加设备/加目录/状态）
- 后端：`lib/services/sync/syncthing_backend.dart`（扫码配对 + 目录定位）
- 配对载荷：`lib/services/sync/sync_backend.dart` 的 `SyncthingPairPayload`
  （二维码内容 = deviceId + apiKey + folderId）

### 桌面端

捆绑或按需下载 `syncthing(.exe)`（校验 sha256），作为子进程启动，经 REST
（默认 `http://127.0.0.1:8384`，`X-API-Key` 认证）控制；共享目录固定为
`NatsumeQuizMaster数据/`（题库 JSON + 知识库包 + 清单）。

### Android 端

经 gomobile 把 Syncthing 的 `lib/syncthing` 编译成 `.aar`，在进程内跑，暴露
同一 REST 接口与共享目录。原生构建步骤（本仓库只交付 REST 客户端 + 目录监听
契约）。

## 扫码配对体验

复用现有 `sync_qr_view.dart` / `sync_scan_screen.dart`：一端生成二维码
（SyncthingPairPayload），另一端扫 → 互相 `addDevice` + `addFolder`，之后
Syncthing 自动持续同步；App 监听目录变化，经 `KbFileService` /
`BankFileService` 自动导入新文件（按题目内容指纹去重）。

## 局域网同步（实现要点 · 2026-10-30 修订）

真机反馈「同 Wi-Fi 下发现不了设备 / 电脑端出现扫码界面 / 临时码显示已配对却连不上」，
据此重写了发现与配对两层，界面上也补了平台适配与诊断入口。

### 发现通道（三路并用，缺一不可）

| 通道 | 端口 | 作用 |
|---|---|---|
| 子网单播扫描（主力） | UDP → 对端 51620/51621 | 逐台扫描各网段主机，单播属于出站流量，不受入站防火墙规则限制 |
| 多播信标（辅助） | UDP 51622（组 `239.192.93.93`） | 广播不可达时的备用通道 |
| 广播信标（辅助） | UDP 51620（定向）+ `255.255.255.255`（兜底） | 部分平台「发送不报错但包不达」，故排在定向广播之后 |

- 绑定后**立即** `broadcastEnabled = true`：Windows 上未开启就向 `255.255.255.255`
  发送，`dart:io` 会异步报错并销毁 socket（`send` 看似成功、包其实没发出）。
- 网卡选择统一走 `lib/services/sync/lan_address.dart`：过滤回环 / APIPA /
  CGNAT，识别 VMware / Hyper-V / Docker / VPN / 蓝牙等虚拟网卡，按分排序、
  真实网卡优先。二维码里的 IP、虚拟网卡判断、`/24` 广播与主机列表推算都由它决定，
  避免把 `VMnet1` 的地址写进二维码。
- socket 被系统关闭后自动重建（统计里的「socket 重建」次数）。

### 配对状态机（`SyncPairState`）

`none → awaitingPeer → verifying → verified / rejected`

- 只有向对端 `GET /sync/info` 带码请求拿到 **200** 才置 `verified`（界面才显示「已配对」）；
  403 = 码不对 / 临时码过期 → `rejected`；连不上 → `awaitingPeer` + 8 秒自动重试。
- 握手同时充当连通性探针：200 就证明 IP / 端口 / 防火墙这条链路是通的。
- 已确认的对端地址会被记住，发现通道被挡住时「立即同步」仍可直连。

### 端口与防火墙

- TCP 51630-51632：同步服务（`/sync/info`、`/sync/exchange`）
- UDP 51620-51622：设备发现
- Windows 安装包 `tools/natsume_setup.iss` 在管理员安装时自动放行上述端口与程序；
  非管理员安装由应用首次运行时的系统防火墙弹窗处理。

### 平台自适应 UI

- 桌面（Windows / Linux / macOS）：设置页直接展示**本机二维码 + 本机识别码 + 手动输入框**，
  不出现「扫码」按钮；误入扫码页会看到「电脑端没有摄像头」的说明页。
- 手机（Android / iOS）：提供「扫码配对」按钮 + 手动输入框。
- 设置页「网络诊断」展开可查看已发/已收包数、监听端口、参与发现的网卡、最近一次错误。

## 许可

Syncthing 为 MPL-2.0；以独立进程/REST 调用方式使用，其文件不并入本仓库。
